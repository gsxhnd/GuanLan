# 产品范围与边界定义

## 1. 产品定位

GuanLan 是一个**单用户、本地运行，覆盖行情数据、分析建议、投资组合记账与复盘的量化工作台**。

系统当前聚焦三件事：

1. 以用户维护的股票池为主要入口获取和展示指定股票的日频市场数据。
2. 记录交易、分红、现金流和估值快照，计算持仓、成本、盈亏和总资产。
3. 基于固定数据版本执行分析、训练和回测任务。
4. 提供状态展示、告警、结果追溯和年度复盘支持。

详细领域对象和字段以 [03-domain-model.md](./03-domain-model.md) 为准。

## 2. 目标用户与运行方式

- **目标用户**：单机自用的研究者或投资者，具备基本股票和量化分析背景。
- **运行方式**：本地部署优先，适配 Linux 主机和资源受限环境。
- **设计重点**：可用、稳定、可追溯，不追求复杂分布式能力。

## 3. 市场范围

当前阶段聚焦：

| 市场 | 当前范围 |
|------|----------|
| A 股 | 用户手动添加的股票代码，预置中证 A500 等指数成分股作为训练数据 |
| 美股 | 用户手动添加的股票代码，后续按数据源能力扩展预置训练数据 |

后续是否扩展港股、加密货币或更高频数据，记录在 [06-open-questions.md](./06-open-questions.md)。

## 4. 当前阶段范围

### 必做

1. 股票池驱动的日频行情初始化、增量更新和质量校验。
2. DuckDB 日频数据底座，包括原始数据、标准化数据、特征数据和版本记录。
3. 预置指数成分股训练数据入库，包括中证 A500 等指数的成分股快照和历史日频数据。
4. 日频数据图表，包括个股 K 线/成交量展示、时间范围切换和数据状态提示。
5. 股票池管理页面，支持查看、添加和删除指定股票代码；已存在于预置训练数据中的股票可直接展示日频数据，未存在的股票触发数据获取任务。
6. 投资组合记账，包括交易记录、现金分红、现金流、持仓成本、总资产图表和盈亏概览。
7. 年度复盘，支持按自然年过滤交易、分红、现金流、估值快照和收益报表。
8. 每日定时分析任务，输出信号、置信度、风险分数和理由摘要。
9. 训练任务、回测任务和基础报告。
10. 告警、系统状态和任务运行追踪。

### 不做

1. 多用户协作、账户体系和权限管理。
2. 自动交易执行、券商自动同步和多账户资金管理。
3. 盘中实时数据、实时分析和流式特征链路。
4. 新闻抓取、事件流、情绪分析和社交媒体监测。
5. 送股、转增股本和复杂税务核算。
6. 面向外部用户的平台化能力。

## 5. 核心对象分组

系统围绕以下对象组展开，字段定义见 [03-domain-model.md](./03-domain-model.md)：

| 对象组 | 覆盖内容 |
|--------|----------|
| 数据资产 | 指数数据集、指数成分股快照、日频行情、个股数据状态 |
| 用户关注范围 | 股票池条目、添加/删除记录、标签、优先级和启用状态 |
| 投资组合 | 交易记录、现金分红、现金流、持仓状态、估值快照、资产快照 |
| 复盘报表 | 盈亏概览、年度收益报表、年度图表和跨年对比 |
| 任务执行 | 数据任务、分析任务、训练任务、回测任务 |
| 结果沉淀 | 分析结果、回测报告、模型版本和数据版本 |
| 运行状态 | 告警事件、服务健康状态、日志入口 |

## 6. 设计原则

1. **单用户优先**：不引入与本地自用无关的权限、组织和协作设计。
2. **任务化优先**：数据更新、分析、训练和回测统一纳入任务模型。
3. **可追溯优先**：结果关联运行时间、数据版本、参数版本、模型版本和状态。
4. **本地可靠优先**：页面、任务和数据存储都优先服务本地部署。
5. **股票池优先**：用户添加指定股票代码后，系统才将其纳入展示、数据更新和每日分析范围。
6. **日频数据优先**：先实现日频数据获取和日频图表，再扩展分析、回测和更高频能力。
7. **训练数据预置**：指数成分股数据只作为训练数据提前沉淀到 DuckDB，不作为用户关注范围的默认入口。
8. **记账独立可用**：投资组合计算必须能在没有日频行情时，仅基于交易、分红、现金流和估值快照运行。

## 7. 核心业务流程

### 7.1 数据初始化

1. 系统按配置预先拉取中证 A500 等训练数据指数的成分股列表并保存成分股快照。
2. 系统以训练数据指数成分股为范围创建历史日频数据初始化任务。
3. 用户在股票池中添加指定股票代码。
4. 若该股票已存在于 DuckDB 预置训练数据中，页面直接读取并展示日频数据。
5. 若该股票不存在于 DuckDB，系统创建该股票的日频数据获取任务。
6. 系统完成数据校验，记录完整率、缺失范围和异常情况。
7. 页面展示个股日频图表、最近成功时间和任务结果。

### 7.2 数据增量更新

1. 系统判断交易日和收盘后更新窗口。
2. 优先按活跃股票池抓取新增日频数据并校验完整性。
3. 将原始数据、标准化数据和质量结果写入 DuckDB。
4. 预置训练数据可按独立任务定期补齐，不影响股票池的用户关注范围。
5. 失败或异常时生成任务记录和告警。
6. 更新总览、数据页、日频图表和服务状态。

### 7.3 每日分析

1. 系统确认目标市场数据已更新并通过基础质量校验。
2. 从活跃股票池中挑选待分析对象。
3. 读取固定数据版本、特征和模型版本。
4. 执行推理和风险评估。
5. 写入分析结果并更新页面状态。

### 7.4 股票池管理

1. 用户进入股票池页面查看当前关注股票。
2. 用户输入指定股票代码并选择市场，系统校验代码格式和数据状态。
3. 若该股票已存在于 DuckDB 预置训练数据中，系统直接标记为可用并展示日频数据。
4. 若该股票没有可用日频数据，系统创建获取任务，任务完成后更新数据状态。
5. 用户可为股票设置标签、优先级、备注和是否参与每日分析。
6. 用户删除股票时，系统将股票池条目标记为停用或移除，不删除已沉淀的历史数据和分析结果。
7. 页面展示股票来源、最近更新时间、数据完整率和可操作状态。

### 7.5 回测

1. 用户选择股票范围、时间区间、基准和参数。
2. 系统创建回测任务并读取指定数据版本。
3. 系统执行回测并生成指标与报告。
4. 用户查看收益、风险、基准对比和运行摘要。

### 7.6 交易入账

1. 用户记录买入或卖出交易，填写日期、股票代码/名称、方向、价格、数量、总费用和备注。
2. 买入交易减少现金余额，增加持仓数量和总成本。
3. 卖出交易增加现金余额，减少持仓数量，并按移动加权平均成本计算已实现盈亏。
4. 清仓后该股票持仓数量归零，并结清该股票全部已实现盈亏。

### 7.7 分红入账

1. 用户记录现金分红，填写日期、股票、每股分红金额或总分红金额。
2. 现金分红增加账户现金余额。
3. 系统在分红日将该股票总成本减去总分红金额，持仓数量不变，平均成本随之下降。
4. 送股和转增字段预留，当前阶段不参与计算。

### 7.8 估值与总资产图表

1. 用户可录入单只股票估值价格，或一次性录入全部持仓合计总资产。
2. 系统根据最新持仓数量计算持仓市值，并与现金余额合成总资产。
3. 支持预留每日收盘价 CSV 导入能力，导入后可回填每日持仓市值和资产快照。
4. 图表展示总资产折线，并支持查看持仓市值、现金余额和总资产构成。
5. 没有估值数据时，图表显示现金余额曲线或提示用户补充价格。

### 7.9 年度复盘

1. 交易记录、分红记录、现金流和估值快照按自然年过滤，默认显示当前年。
2. 年度报表汇总已实现盈亏、分红收入、净出入金、期初资产和期末资产。
3. 年度盈亏可下钻到单只股票的已实现盈亏和分红贡献。
4. 年度图表展示资产走势和按股票分组的收益贡献。
5. 跨年对比将各年度关键指标并排展示，辅助长期复盘。
