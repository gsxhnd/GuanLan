# 工程路线图

本文档维护 GuanLan 的工程推进顺序、阶段目标和出口条件。

| 文档 | 作用 |
|------|------|
| [01-product-scope.md](./01-product-scope.md) | 产品边界与 MVP 范围 |
| [02-architecture.md](./02-architecture.md) | 进程模型、分层与 API |
| [03-domain-model.md](./03-domain-model.md) | 领域对象与任务状态 |
| [04-tech-stack.md](./04-tech-stack.md) | 技术选型与硬件约束 |

**执行假设**：1 人全栈、单用户、本地部署、资源受限环境（Jetson 8GB）优先。

## 路线图原则

1. 先定模型和任务底座，再建设页面和业务闭环。
2. 先支持用户手动添加股票池并按股票代码获取日频数据，再扩展市场范围。
3. 先完成日频数据获取、日频图表和投资组合记账，再增强分析、回测和策略能力。
4. 记账与复盘必须在没有日频行情时独立可用。
5. 先保证结果可用、状态可见、失败可处理，再增强策略能力。
6. 当前阶段未达到出口条件时，不进入下一阶段。
7. 中证 A500 等指数成分股数据作为预置训练数据提前写入 DuckDB，不作为默认用户股票池。
8. **整库单写者**：仅 `cmd/api` 打开 `data/guanlan.duckdb`；Python crawler / prediction 无状态，不直连应用库。

## 平台基线（已落地）

三进程本地运行模型与包边界已完成，后续阶段在其上增量交付：

| 项 | 现状 |
|----|------|
| 进程 | `cmd/api :8080` + `quant.crawler :50061` + `quant.ml.serving :50062` |
| HTTP | Kratos `transport/http` + `protoc-gen-go-http`；OpenAPI 由同一套注解生成 |
| 包边界 | `internal/biz`（领域）/ `orchestrator`+`cron`（编排）/ `data`（DuckDB 原语，无出向 RPC） |
| Proto | `quant.v1`：`api.proto`（对外 HTTP）+ `crawler.proto` / `prediction.proto`（内部 gRPC） |
| Python | 顶层包 `quant/`：crawler 纯函数取数；training 读 Parquet 快照；serving 懒加载模型 |
| 同步链路 | cron/HTTP → orchestrator → crawler 流式回传 → `Store.Ingest*` 写库 |

细节见 [02-architecture.md](./02-architecture.md)、[04-tech-stack.md](./04-tech-stack.md)。

## Phase 0：工程基线与领域模型定稿

### 目标

确定后续页面、任务和结果共用的领域模型，降低结构性返工风险。

### 关键任务

- [ ] 定稿核心对象、任务状态、任务公共字段和结果追溯字段。
- [ ] 明确页面通用能力：状态标签、更新时间、失败原因、重试入口和日志入口。
- [ ] 明确本地部署基础约束：数据库路径、日志策略、任务执行方式和缓存边界。
- [ ] 明确日频行情字段、图表最小展示字段、股票池驱动的数据获取范围和预置训练数据范围。
- [ ] 明确交易、分红、现金流、持仓、估值快照和年度复盘字段。
- [ ] 明确移动加权平均成本、分红降成本、清仓结算和总资产计算规则。

### 出口条件

[03-domain-model.md](./03-domain-model.md) 覆盖当前阶段的页面字段、任务流程和结果追溯需求。

- [x] 实现状态标签、失败原因面板、日志入口和重试按钮等通用组件。
- [x] 建立日频数据图表占位，明确个股选择、日期范围和加载/缺失状态。
- [x] 建立股票池页面占位，明确股票代码输入、添加、删除、启用状态和空状态。

## Phase 2：统一任务框架与 HTTP API

### 目标

实现任务管理和结果追溯底座，为数据、分析、训练和回测提供一致执行模型；对外仅经 `cmd/api` 提供 HTTP/JSON。

### 关键任务

- [x] 初始化 `cmd/api`：DuckDB、`internal/biz`、orchestrator、cron，以及 go-http 注册。
- [x] 集成 DuckDB 并创建基础表结构（schema 仅在 Go 侧维护）。
- [x] 实现任务状态机、公共字段和版本追溯。
- [x] 实现定时触发（`robfig/cron`）、手动触发和重试机制。
- [x] 通过 `protoc-gen-go-http` 暴露当前阶段 `/api/...` HTTP/JSON API。
- [x] 实现股票池基础 API，支持列表查询、添加指定股票代码、删除或停用指定股票代码。
- [x] 建立投资组合记账基础表，覆盖交易、分红、现金流、持仓、估值快照和资产快照。
- [x] 实现投资组合基础 API，支持交易、分红、现金流、持仓、估值、总资产和年度复盘查询。

### 出口条件

任务可被创建、调度、执行、重试，并能记录完整状态、日志入口和版本信息；股票池 API 可完成指定股票代码的添加和删除；投资组合 API 可记录交易、分红、现金流并查询持仓和总资产。

## Phase 3：DuckDB 数据底座和日频数据接入

### 目标

建立稳定的日频数据底座，支持股票池指定股票的数据获取、预置训练数据入库、每日更新和图表展示。

### 关键任务

- [x] 拉取并保存中证 A500 等训练数据指数的成分股快照。
- [x] 将训练数据指数成分股的历史日频数据提前写入 DuckDB。
- [x] 以活跃股票池为主要范围接入 yfinance、Qlib 和后续补充源接口。
- [x] 用户添加股票代码时先检查 DuckDB 已有数据，缺失时创建该股票的数据获取任务。
- [x] 实现无状态 crawler gRPC（`FetchDailyBars` 流式每股一消息）；由 `cmd/api` 的 `Store.Ingest*` 写库。
- [x] 实现数据清洗、质量校验和异常记录（crawler 侧纯函数）。
- [x] 建立行情与版本管理相关表；训练特征由 `quant/ml/features` 定义，应用库不再维护无人读的特征宽表。
- [x] 建立日频行情查询 API，支持按股票代码和日期范围读取价格、成交量和质量状态。
- [x] 建立数据状态页面：指数、个股、日频图表和任务记录。
- [x] CSV 股票池导入走 api HTTP（`quant.tools.pool_csv`），不直连 DuckDB。

### 出口条件

股票池中的指定股票可按需获取或直接读取 DuckDB 既有日频数据；预置训练数据可完整初始化并增量更新；个股日频图表可展示价格和成交量，质量校验结果可追溯；同步链路在三进程下可端到端入库。

## Phase 4：投资组合记账与资产复盘闭环

### 目标

实现交易记录、分红、现金流、持仓成本、总资产图表和年度复盘，使记账能力在没有日频行情时也可独立运行。

### 关键任务

- [ ] 实现交易记录页面和 API，支持买入、卖出、总费用和备注。
- [ ] 基于移动加权平均成本法自动重算持仓数量、总成本、平均成本和已实现盈亏。
- [ ] 实现现金分红记录，现金入账并自动下调对应股票总成本和平均成本。
- [ ] 实现出入金现金流记录，现金余额由交易、分红和出入金流水重算。
- [ ] 实现手动估值快照和每日收盘价 CSV 导入接口。
- [ ] 实现总资产图表，支持总资产折线、持仓市值 vs 现金构成和现金曲线。
- [ ] 实现盈亏概览和单只股票详情，展示持仓、市值、未实现盈亏、已实现盈亏和累计分红。
- [ ] 实现年度复盘，支持自然年过滤、年度收益报表、股票贡献图表和跨年对比。
- [ ] 支持按年份范围导出交易记录、分红记录和估值快照为 CSV/Excel。

### 出口条件

仅凭交易、分红、现金流和稀疏估值快照，即可计算现金余额、持仓、成本、已实现盈亏、未实现盈亏和总资产曲线；年度复盘口径与流水日期过滤一致。

## Phase 5：股票池与每日分析闭环

### 目标

完善股票池管理并接入每日分析，产出可追溯的分析结果。

### 关键任务

- [ ] 完善股票池页面，支持手动添加、删除指定股票代码、标签、优先级、启用状态和数据获取状态。
- [ ] 删除股票池条目时保留历史数据、历史分析结果和回测结果。
- [x] 建立 `quant/ml/features`（training / serving 共用列定义）与 baseline training CLI。
- [x] 实现 prediction gRPC 骨架（懒加载 `data/models`；无模型时 UNIMPLEMENTED）及 api 侧批量/按需预测入队与落库。
- [ ] 完善每日分析流程：数据校验、特征读取、模型推理、信号生成（含置信度、风险分数、理由摘要）。
- [ ] 存储分析结果并支持历史追溯（页面与查询完善）。
- [ ] 建立 GRU（或后续正式模型）训练流程和 `model_versions` 管理闭环。
- [ ] 推理侧输入由 api 导出的快照 / 请求载荷提供，serving **不**打开应用 DuckDB。

### 出口条件

股票池页面可管理关注股票；每日分析可自动或手动触发，结果包含信号、置信度、风险分数和理由摘要，并支持历史追溯。

## Phase 6：训练与回测闭环

### 目标

建立可重复训练和可追溯回测能力，完善系统核心闭环。

### 关键任务

- [ ] 创建回测任务，支持股票范围、时间区间、基准和参数。
- [ ] 基于固定数据版本（或 Parquet 快照）执行回测。
- [ ] 生成收益、风险、基准对比和指标报告。
- [ ] 支持回测结果对比。
- [ ] 管理批量训练、验证和超参优化（训练读快照，不打开应用 DuckDB）。
- [ ] 建立告警和系统状态监控页面（`/healthz`、`/metrics` 已具备进程级探针）。

### 出口条件

回测结果可追溯、可对比，告警可统一查看，系统健康状态可监控。
